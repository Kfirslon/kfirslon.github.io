Lead Intelligence Pipeline

A self-updating system that finds, ranks, and delivers fresh sales leads every morning, replacing a costly manual vendor feed for a lending client.

The problem

The client relied on purchased lead lists, but the lists were difficult to prioritize and often lacked enough context to know whether a lead was current or actionable.

The underlying data was public, but each state published it differently. Some provided large files, others required page-by-page retrieval, and others published multiple files that had to be combined. I built a separate ingestion process for each source and normalized the information into one consistent dataset.

The next challenge was turning a business filing into a person a sales rep could actually contact. That required matching businesses to officers and other contacts across public business registries.

How it runs, every morning

01

Collect

Every weekday, the system pulls new financing filings from 11 state sources. Each source uses a different API, file format, or retrieval method, so the system has a dedicated ingestion process for each one.

02

Clean and dedupe

Records are normalized into a consistent format and matched against the existing dataset, so the same business never appears twice. The stored dataset is the system's memory.

03

Enrich

Missing information is supplemented using public web and mapping sources, turning a basic filing into a more actionable sales record.

04

Classify with an LLM

Known lenders are classified with deterministic rules. Unknown lenders are sent to an LLM, and the result is cached so repeated classifications do not require another model call.

05

Score and rank

Each lead receives a score based on filing freshness and where it falls within its renewal window. The highest-priority leads rise to the top of the daily list.

06

Deliver

Results are delivered through a web dashboard, a daily email digest, and spreadsheet-ready output.

Turning a filing into a phone call

A filing identifies a business, but a sales rep needs a person they can contact. I matched businesses to officers across state business registries and resolved reachable contacts where possible.

About 79,000 owner names were resolved, with a confidence level attached to each match so users could tell stronger matches from less certain ones.

Keeping it reliable

A daily pipeline can quietly fail if a source changes format or a step starts returning incomplete data. I built checks around the workflow to catch those failures before they become bad leads.

Weekly integrity audit

Every Sunday, the system re-checks the week's intake against the live government sources, compares totals against the database, and looks for duplicate keys and missing fields. If something is wrong, the audit fails clearly instead of letting bad data go unnoticed.

Safe failure paths

The LLM layer falls back to deterministic rules when a model is unavailable. Optional integrations also fall back to a working mode when credentials or external services are unavailable.

Human review built in

Records the classifier cannot confidently categorize are placed into a review queue instead of being silently guessed.

What I'd build next

Today the pipeline uses deterministic scoring with an LLM for classification. The next step would be a more agentic workflow that researches each lead, gathers relevant public signals, and prepares an auditable recommendation for the sales team.

I would also add immediate source monitoring, so that if a government source changes its format the system alerts me that morning instead of waiting for the weekly audit.
